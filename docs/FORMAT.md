# 文件格式

hMETIS 首行为 `m n [fmt]`。m 可为 0，n 至少为 1。格式编号与权重位置如下。

| fmt | 超边行 | 顶点权重行 |
|---|---|---|
| 省略、0、00 | 针脚列表 | 省略，默认 1 |
| 1、01 | 边权，随后是针脚列表 | 省略，默认 1 |
| 10 | 针脚列表 | 超边后每顶点一行正整数 |
| 11 | 边权，随后是针脚列表 | 超边后每顶点一行正整数 |

针脚编号从 1 开始。空格和制表符可分隔字段，接受 LF、CRLF、文件末尾无换行和整行 `%` 注释。前导空白后的 `%` 也视为整行注释。格式错误报告物理行号，内存构造错误的 line 为 0。

每条超边至少有一个针脚，重复或越界针脚、零/负权重、截断、额外记录、非十进制字段和溢出均报错。空边记录、行内注释和多约束扩展语法会被拒绝。孤立顶点、单点超边和零条超边可被保留。

分区文件为每个顶点一行 `0` 或 `1`，顶点顺序对应输入编号顺序。接受可选末尾换行。verify 复核行数、编号、非空性、容量及目标值。

JSON schema_version 为 1。`cut_net`、`connectivity`、`part_weights`、`capacities`、总顶点/边权及 `run.initial_cut` 使用十进制字符串。规模、分区顶点数、seed 和工作计数使用精确范围内的 JSON 数字。`max_to_average` 为用于展示的浮点比值。

CLI 成功时 stdout 输出一个 JSON 对象。错误对象包含 `status=error`、`code`、`line`、`message`。帮助命令输出文本。partition 的 `run` 对象记录种子、初始目标、预算和实际工作；inspect 与第三方 verify 不包含求解工作数据。

输出要求使用新路径。所有内容先在目标目录中创建 `.moonhyperpart.tmp` 临时文件，全部写完并同步后才发布目标文件名。发生 I/O 错误时清理本次拥有的临时文件和已发布文件。进程中断或掉电可能留下临时文件，也可能只发布了报告文件。重试前应核对已有输出状态。

四模式定义依据 [Mt-KaHyPar 的格式文档](https://github.com/kahypar/mt-kahypar/blob/master/mt-kahypar/io/docs/FileFormats.md)。
