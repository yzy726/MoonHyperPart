# 容量与指标

内存 API 接收两个显式正 Int64 容量。所有顶点恰好分配一次，分区编号为 0 或 1，两个分区均非空，分区顶点权重之和不得超过相应容量。

CLI 的容差 ε 用最多三位小数表示。令 q 为 ε 的千分数整数，统一容量为 `ceil(total * (1000 + q) / 2000)`。实现先将 total 分解为除以 2000 的商和余数，避免直接乘法的中间溢出。q 的范围为 0 到 1000，最终容量不超过 total。

cut-net 是跨分区超边的正整数权重之和。connectivity 是每条边权乘以其涉及分区数减一，再求和。二分时两值相等。本版本的优化目标为二分 cut-net。

实际最大/平均比值为 `2 * max(W0,W1) / total`。它反映实际分区权重。小图的容量向上取整可能使这个比值超过 `1 + ε`，判断可行性使用公布的整数容量。

独立验证器只接受原始图、最终分区和容量，检查覆盖、编号、非空性与容量，再遍历全部超边。图的总边权预先检查为 Int64 范围，因此二分 cut-net 的累计不会溢出。

CLI 中 `impossible` 指已证明的必要条件失败，`search_exhausted` 指有界搜索未找到划分。可行解的局部改进若触及预算，仍返回完整且已验证的解，并记录 `budget_limited=true`。目标最优性只在指定小例子中由枚举证明。
